## Scope and Method

1. **審計範疇**：全量掃描 `dashboard/story/*.json`，逐話逐行解析對白資料流。
2. **`cleanName` 語意對齊**：精確鏡像 `AvatarService.cleanName` 的合稱拆分 (`(/[、＆&]|和|與/)[0]`)、全半形括號過濾 (`（...）` / `(...)`) 與結尾「的聲音」移除。
3. **`DialogueNormalizer` 語意對齊**：精確鏡像現行連線相鄰、發言人同名、語音相容 (`!voice || last.voice === voice`) 的合併判定。
4. **身份與數值定義邊界**：
   - 本稽核將所有 `integer > 0` 視為語法上的 Concrete `unit_id`。
   - 部分低數值 ID（例如 `1`, `2111`, `2131`）可能為通用 NPC、動物型態或系統內部代號，不必然等同於已證明的可玩角色獨立身份。
   - 因此本報告將不同 `unit_id` 謹慎定義為 **Variant-Sensitive / Identity-Sensitive** 差異，將 Normalizer 合併事件定義為 **Unit ID Information Loss**，不直接宣稱所有案例皆為角色顯示錯誤 (Wrong Character)。

## B. cleanName Collision Analysis

當不同 Raw Names 經 `cleanName` 規則簡化後歸併至同一查詢 Key 時，評估其是否會造成頭像與卡面解析的身份錯置。

### 修正後嚴謹風險等級定義
- **HIGH**：該群組內**至少存在一對 Raw Names**，各自具備 Concrete `unit_id` 且**集合完全互斥 (A ∩ B = ∅)**。
- **MEDIUM**：無互斥 pair，但集合間存在差異（如 overlap / subset / superset）或部分 Raw Name 含有 missing unit_id 之異格塌縮。
- **LOW**：所有 Raw Name 觀察到的 Concrete `unit_id` 集合完全一致且無 missing 衝突。
- **UNKNOWN**：該群組內所有 Raw Name 均完全無 `unit_id` 資訊。

## E. Name-Only Avatar Resolution Exposure

### 前端渲染機制與實際暴露面分析
1. **對白氣泡 (Dialogue Bubbles)**：
   - 現行 `DialogueView` 在渲染對白氣泡時，**已實質優先採用行級 `item.unit_id`** (`AvatarService.getAvatarHtmlByUnitId(overrideUnitId, realName, speakerAvatars)`)。
   - 只有在該行對白缺少 `unit_id` 時，才會降級至純名稱解析 (`AvatarService.getAvatarHtml(realName, speakerAvatars)`)。
2. **頂部角色徽章 (Speaker Badges)**：
   - 角色徽章列仍主要依賴發言人姓名透過 `AvatarService.getAvatarHtml(name)` 查詢全域靜態映射表。
3. **核心暴露風險定位 (Primary Runtime Exposure)**：
   - `DialogueNormalizer.normalize` 是在 `DialogueView` 渲染之前執行的前置純資料清洗層。
   - 當 `DialogueNormalizer` 發生連續同名台詞合併時，若後一行具有不同 `unit_id`，該 `unit_id` 會被靜默捨棄，導致原本具備行級 ID 識別能力的 `DialogueView` 無法接收到該行的真實 `unit_id`。

- **具備 Concrete `unit_id` 的發言人對白筆數**: **1,162,394 / 1,207,582** (96.26%)
- **涉及同名稱多實體的發言人**: **895 種角色**
- **涉及 HIGH 風險 cleanName 碰撞的群組**: **126 組**

## Conclusions & Recommended Next Steps

### 實證結論 (Evidence-Based Findings)
1. **DialogueNormalizer 存在確證的資訊遺失 (Confirmed Information Loss)**：
   - 在 131 篇劇情話數中發生了 523 次不同 `unit_id` 的連續同名台詞合併事件，導致行級 `unit_id` 在渲染前遺失。
2. **cleanName 碰撞風險已精確收斂**：
   - 採用 Disjoint Pair 嚴謹判定後，確認了真正具有互斥實體衝突的 HIGH 風險群組與 subset/overlap 的 MEDIUM 群組。
3. **前端渲染層已具備 row-level unit_id 基礎**：
   - 對白氣泡渲染已優先採用 `overrideUnitId`，只要 Normalizer 不抹除 `unit_id`，氣泡層級即可精確顯示異格與換裝頭像。

### 建議後續步驟 (Recommended Next Step)

> [!TIP]
> **建議啟動 `A2 TARGETED FIX INVESTIGATION`**：
> 1. 研究在 `DialogueNormalizer` 中加入 `unit_id` 一致性保護 (`last.unit_id === item.unit_id`)，防止型態切換台詞被合併。
> 2. 評估頂部角色徽章 (Speaker Badges) 是否需改進為多型態支援或保持現有章節代表頭像。
